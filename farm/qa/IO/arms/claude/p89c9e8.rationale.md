# p89c9e8: ABSTAIN

**What sets the clock.** At T0 every critical setup path runs from one flop (i976, dfrtp_2) to all 64 bits of G01 and G04. Each path goes flop -> 3-level buf_2 fanout tree -> per-port buf_2 -> clkdlybuf4s25_1 port buffer -> pin. Arrival is about 3.62 ns at ss, so the fixed point is about 4.8 ns before the resizer acts. Register-to-register paths come next (about 4.29 ns). G06 and RST have large slack. G02, G05 and G07 are unconnected, and G03 is a tie cell.

**Why no move.** All 64 bits carry the same signal, so bus order does not matter; only the spread of the sinks does. The stock pins already fill the most compact space that the fixed G02 pins leave: N 27.8-73.8 um plus E 56-72 um, beside the output cone. A 32-bit group can go only to W, or to N+W when both groups move, so any move splits the cone. I checked the W1, W2 (same slots as W3) and N2/N3+W windows with the validator. A split adds a long trunk to a high-level tree net (about +8 fF, or +50-60 ps at ss on every output). It also probably deepens the chain-like repair tree and pushes output buffers into the register-logic area. W pins save only about 1 fF of wire per output. A ~50 ps arrival change moves the final score by about one 0.05 ns step.

**Expected effect** (change in critical output arrival; confidence):
- G01 or G04 to W1/W2/W3: worse, +20 to +60 ps; 0.6.
- One group to N and the other to W: worse; 0.6.
- G05/G07/G03/G06 moves: no timing effect, noise only; 0.8.

Keeping the tool's pins gives the same result as the stock baseline.
